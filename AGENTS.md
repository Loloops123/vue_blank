# Инструкции для работы с проектом

Этот файл действует для всего репозитория. Перед изменениями изучай связанные
исходники и конфигурацию. Если описание здесь расходится с кодом, ориентируйся
на актуальную конфигурацию и обновляй инструкции при изменении устройства проекта.

## Назначение и стек

Проект — стартовый шаблон SPA, без прикладного backend и бизнес-логики.
На главной странице отображаются заголовок и демонстрационная кнопка.

- Vue 3.5, Composition API, однофайловые компоненты с TypeScript.
- Vite 7, TypeScript 5.9, ESM (`type: module`).
- Vue Router 4 с HTML5 history; Pinia 3 для общего состояния.
- Tailwind CSS 4 через `@tailwindcss/vite`.
- `unplugin-icons` с компилятором `vue3` и коллекциями `@iconify/json`.
- Vitest 4 и happy-dom для unit-тестов.
- Storybook 10 для компонентов, документации и браузерных тестов.
- ESLint 9, Oxlint, Prettier, Husky, lint-staged и commitlint.

## Окружение и установка

- Используй pnpm: в репозитории хранится `pnpm-lock.yaml`, скрипты и хуки
  также используют pnpm. Не добавляй lock-файлы других менеджеров пакетов.
- Диапазон Node.js в `package.json`: `^20.19.0 || >=22.12.0`.
- Установка зависимостей: `pnpm install`; для воспроизводимой установки
  по существующему lock-файлу — `pnpm install --frozen-lockfile`.
- Не редактируй `pnpm-lock.yaml` вручную. Обновляй его через pnpm, когда меняются
  зависимости; не обновляй зависимости попутно с несвязанной задачей.

## Соглашения по коду

- Следуй стилю соседних файлов, используй `<script setup lang="ts">`.
  Не переводить существующие компоненты на Options API без причины.
- Компоненты именуй в PascalCase. Для компонентов с историями используй
  существующий образец: `src/components/ComponentName/ComponentName.vue`
  и `ComponentName.stories.ts` рядом.
- Страницы размещай в `src/view`, stores — в `src/store` с именами
  `useSomethingStore.ts`. Не переименовывай каталоги ради привычной структуры.
- Алиас `@/` указывает на `src/` и настроен в Vite и TypeScript.
  Для соседних файлов уместны относительные импорты.
- Описывай props и emits типами. Учитывай `strictTemplates` и
  `noUncheckedIndexedAccess`; проверяй потенциально отсутствующие значения.
- Используй Pinia для общего состояния, локальные `ref`/`computed` — для
  состояния компонента. Существующий store реализован через setup-функцию.
- Для оформления используй Tailwind CSS 4; глобальные стили добавляй в
  `src/assets/main.css`, локальные при необходимости — в scoped styles.
  Не добавляй конфигурацию Tailwind старых версий без необходимости.
- Для новых интерактивных элементов сохраняй семантику HTML, доступность
  с клавиатуры и видимый фокус. Сохраняй используемые тестами `data-testid`.
- Форматирование определяет `.prettierrc.json`: 2 пробела, одинарные кавычки,
  без точек с запятой, завершающие запятые, LF, ширина 80 символов,
  один атрибут шаблона на строку. Классы Tailwind сортирует плагин Prettier.
  В `.editorconfig` указан предел 100, но при форматировании применяй Prettier.
- Импорты и экспорты сортирует `simple-import-sort`; не оставляй
  неиспользуемые импорты. Не отключай правила линтеров и проверки типов
  ради обхода ошибки без обоснованной необходимости.

## Команды

| Команда                | Действие                                                              |
| ---------------------- | --------------------------------------------------------------------- |
| `pnpm dev`             | Сервер Vite, обычно порт 5173; доступен на `0.0.0.0`                  |
| `pnpm storybook`       | Storybook на порту 6006                                               |
| `pnpm test:unit`       | Однократный запуск `src/**/*.spec.ts` в happy-dom                     |
| `pnpm test:storybook`  | Тесты историй в headless Chromium через Playwright                    |
| `pnpm lint:types`      | Проверка TypeScript через `vue-tsc --build`                           |
| `pnpm lint:oxlint`     | Oxlint с автоматическими исправлениями                                |
| `pnpm lint:eslint`     | ESLint с автоматическими исправлениями и кешем                        |
| `pnpm lint:commit`     | Проверка сообщения коммита через `commitlint --edit`                  |
| `pnpm lint:all`        | Последовательный запуск всех скриптов `lint:*`, включая `lint:commit` |
| `pnpm build:dev`       | `vite build`, без отдельной проверки типов                            |
| `pnpm build:ci`        | Проверка типов и `vite build`; результат в `dist/`                    |
| `pnpm storybook:build` | Статическая сборка Storybook в `dist-storybook/`                      |
| `pnpm prettier:format` | Форматирование всего репозитория с записью файлов                     |
| `pnpm knip`            | Поиск неиспользуемых файлов, экспортов и зависимостей                 |

Оба скрипта `build:dev` и `build:ci` запускают обычный `vite build`;
название `build:dev` не означает Vite mode `development`.
`lint:all` не является проверкой только исходников: учитывай зависимость
`lint:commit` от контекста сообщения коммита.

## Проверка изменений

- Выбирай проверки по затронутой области. Для изменения только документации
  достаточно проверки содержимого и форматирования:
  `pnpm exec prettier --check AGENTS.md`.
- Для изменений TypeScript/Vue запускай `pnpm lint:types` и относящиеся
  к изменению тесты. Перед сдачей изменений приложения проверяй сборку
  `pnpm build:ci`, если окружение позволяет её выполнить.
- Для проверки ESLint без изменения файлов используй
  `pnpm exec eslint <пути>`; для Prettier —
  `pnpm exec prettier --check <пути>`. Автоисправления и форматирование
  ограничивай затронутыми файлами, чтобы не создавать посторонний diff.
- Unit-тесты размещай рядом с кодом как `*.spec.ts`: именно этот шаблон
  включён в `vitest.config.ts`. Используй явные импорты из `vitest`.
  В тестах Pinia создавай свежую активную Pinia в `beforeEach`, как в примере.
- Добавляй тесты на новое поведение и исправляемые ошибки, когда это полезно;
  не создавай формальные тесты ради документации или простого форматирования.
- Истории имеют расширение `.stories.ts`, используют типы `Meta`, `StoryObj`
  и при необходимости `play` с `storybook/test`. Для изменений поведения
  компонентов проверяй относящиеся истории через `pnpm test:storybook`.
- Для браузерных тестов требуется установленный Chromium Playwright.
  Если его нет, установка: `pnpm exec playwright install chromium`.
  Изменения конфигурации Storybook проверяй также `pnpm storybook:build`.
- Не выдавай невыполненную проверку за успешную. В отчёте указывай выполненные
  проверки и ограничения окружения; отличай существующие ошибки от новых.

## Git, конфигурация и границы изменений

- Сохраняй незакоммиченные изменения пользователя. Не делай несвязанные
  рефакторинги, массовое форматирование и удаления файлов.
- Хук `pre-commit` запускает `pnpm exec lint-staged`: TypeScript/Vue проходят
  ESLint и Prettier, JSON/Markdown/HTML/CSS — Prettier.
  Хук `commit-msg` проверяет Conventional Commits через commitlint.
- Не отключай хуки ради прохождения коммита. Создавай коммиты и отправляй
  изменения только в рамках запроса пользователя.
- Не редактируй вручную артефакты `node_modules/`, `dist/`, `dist-ssr/`,
  `coverage/`, `dist-storybook/`, `storybook-static/` и `*.tsbuildinfo`.
  Проверяй, что результаты сборок и кеши не попали в итоговый diff:
  `dist-storybook/` сейчас не указан в `.gitignore`.
- Не публикуй секреты и содержимое локальных env-файлов. Значения `VITE_*`
  доступны клиентскому коду, поэтому секреты туда помещать нельзя.
  При добавлении переменных окружения обновляй типы в `env.d.ts`;
  сейчас там объявлен `VITE_APP_TITLE`.
- При изменении маршрутизации учитывай `createWebHistory` и
  `import.meta.env.BASE_URL`: сервер размещения должен возвращать `index.html`
  для клиентских маршрутов.
- При изменении команд, структуры или инструментов актуализируй этот файл
  и соответствующие разделы README.
